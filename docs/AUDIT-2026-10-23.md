## How to work on this list

- Do one item per PR. Before pushing, run `npm test` and `npx tsc --noEmit`, then check the change in the browser on `/preview…` at 375 px width.
- **Windows trap:** never write regexes or code through `node -e` or bash heredocs. They silently strip backslashes (`\d` becomes `d`) and turn `\b` into a backspace character. Use the editor or Write tools. After editing, check with `grep -rnP '\x08' src` (should print nothing).
- Most source files have CRLF line endings. Multi-line edits can fail to match. Converting a file with `sed -i 's/\r$//' file` is safe because git normalises line endings.
- Severity: **P1** = wrong data or a broken feature, **P2** = confusing, **P3** = polish.

## A. Bugs (wrong data or broken behaviour)

**A1 · P1 · Settings saves made-up profile values**
- **Where:** `src/app/settings/page.tsx:45-95` and the payload at `:127-146`.
- **Problem:** if a field is empty in the database, the form falls back to `DEPARTMENTS[0]` (Aerospace), `division: "D1"`, `hostel: "Hostel 16"` and `HASMED[0]` ("Entrepreneurship"). Pressing Save writes these as the student's real profile. Notice targeting then goes wrong.
- **Fix:** default to `""` with a "Choose…" placeholder option, as `WelcomeWizard.tsx` does. Only write fields the student actually set. Remove `hasmed` from the payload; the HASMED now comes from the course picker.
- **Verify:** open `/preview/settings` with an empty profile and press Save; no Aerospace / D1 / Hostel 16 values should appear.

**A2 · P1 · Pressing Enter inside My courses submits the whole Settings form**
- **Where:** `settings/page.tsx:217`. The `<form>` wraps `CoursePicker` (search input) and `CoursesEditor` (code, slot and venue inputs).
- **Problem:** Enter in "Find any course" or "Add by code" saves the profile and shows "Saved" instead of adding the course.
- **Fix:** move My courses, Moodle, Alerts and Privacy outside the `<form>`, or make each panel its own form. Also see C1, which removes the shared form entirely.

**A3 · P1 · Changing division in Settings doesn't change your courses**
- **Where:** `settings/page.tsx:252-263` and `CoursePicker.tsx:71-80`.
- **Problem:** a student who switches D3 → D4 keeps the D3 courses and timetable.
- **Fix:** when the division changes and saved courses came from the old division, offer "Switch your common courses to D4?". On Yes, replace the rows from `coursesForDivision(old)` with `coursesForDivision(new)`.

**A4 · P1 · The "Delivery" panel does nothing**
- **Where:** `settings/page.tsx:28-32` and `:320-347`.
- **Problem:** it offers "Evening email digest at 6 PM", but nothing on the server reads `delivery_preference`. The real digest is the 7:30 morning one in `DigestPicker`. Students see two contradicting email settings.
- **Fix:** delete the Delivery radio choices. Move "Personal email (optional)" next to `DigestPicker` in the Alerts panel, since the digest email goes to `personal_email`.

**A5 · P1 · The morning digest reaches almost nobody**
- **Where:** `DigestPicker.tsx:24` (`data?.digest || "push"`) and the database default.
- **Problem:** the default is a phone alert, but very few students have alerts on (0 push devices last time I checked). So the digest silently goes nowhere.
- **Fix:** if the student has no push subscription, default to `email`. Show "Phone alert (turn on alerts above first)" as disabled until push is on.

**A6 · P2 · Notification message is iPhone-only for everyone**
- **Where:** `PushToggle.tsx:73-74`.
- **Problem:** "Notifications aren't available in this browser — On iPhone, tap Share → Add to Home Screen" shows on Android and desktop too.
- **Fix:** detect iOS (`/iPhone|iPad/.test(navigator.userAgent)`) and not-yet-installed (`!matchMedia('(display-mode: standalone)').matches`) for the iPhone text. Otherwise say "This browser doesn't support alerts. Try Chrome."

**A7 · P2 · Web reader files duplicates**
- **Where:** `src/lib/server/webSources.ts`. The dedupe is `sender + subject`.
- **Problem:** the model rewords titles between runs ("Applications invited for UCEED" vs "Applications are invited for UCEED (…)"), so the same item gets filed twice.
- **Fix:** dedupe on the item URL first (store it in `items.links[0]`, check before filing). Fall back to a normalised title (lowercase, strip punctuation and years).

**A8 · P2 · Timetable evening view shows an empty "today"**
- **Where:** `TimetableView.tsx`, phone list view.
- **Problem:** on Friday evening the phone view opens on Friday ("Nothing scheduled on Fri.") instead of the next class day. The Fri chip is also cut off at the right edge.
- **Fix:** if today's classes are over, select the next day that has classes, as `boardFor()` does in `src/app/page.tsx:22`. Call `scrollIntoView({inline:"center"})` on the selected day chip.

**A9 · P3 · Test time bombs**
- **Problem:** timetable tests broke on 23 Oct because they used "23 October 2026" with the real clock. I pinned those in `test_timetable.mjs`.
- **Fix:** search the other `test_*.mjs` files for hard-coded 2026 dates used without a fixed `now` and pin them the same way.

## B. Setup and first-run confusion

**B1 · P2 · Log in vs Sign up tabs**
- **Where:** `src/app/login/page.tsx:243-267`.
- **Problem:** both tabs do the same thing (email, then a code). A new student doesn't know which to pick, and picking Log in fails with "no account".
- **Fix:** one form, "Continue with your IITB email", that creates the account if it's missing. Send `mode: "signup"` to `/api/auth/send-code` always, or merge the modes on the server.

**B2 · P3 · Login loading screen shows a different heading**
- **Where:** `login/page.tsx:223-238`.
- **Problem:** it says "Welcome to Campus Daily" under the logo, which already says Campus Daily, then jumps to the form.
- **Fix:** show the same layout with a spinner in place of the form.

**B3 · P2 · Divisions list may be incomplete**
- **Where:** `src/lib/constants.ts:21` (`DIVISIONS = ["D1".."D4"]`).
- **Fix:** check the real number of 2026 first-year divisions against ResoBin data (the catalog has division names in `catalog-autumn-2026.ts`) and generate the list from it.

**B4 · P3 · "Board" jargon**
- **Where:** "Open my board" (`WelcomeWizard.tsx:308`), "Set up your board" and "Save & open my board" (`settings/page.tsx:205, :391`), "Board only".
- **Fix:** say "Go to Campus Daily" / "Finish". Also remove the legacy `?onboarding=1` mode in Settings, since `/welcome` replaced it.

**B5 · P3 · Ask suggestion sounds like a one-off action**
- **Where:** `AskBox.tsx:7`.
- **Problem:** "Send my digest by email" changes a setting, but reads like it emails something now.
- **Fix:** rename it to "Get my morning digest by email".

## C. Settings: too many sections, mixed save behaviour

**C1 · P2 · Mixed saving**
- **Problem:** Profile, Interests and Delivery need the sticky "Save" button. Courses, Moodle, alerts, digest and theme save instantly. Students will change an interest, leave, and lose it.
- **Fix:** auto-save everything (debounce 600 ms, then show "Saved ✓" next to the panel title). Delete the sticky `.save-bar`.

**C2 · P2 · Eight sections is too many**
- **Where:** `SettingsLayout.tsx:6-15`. On a phone the tab row overflows ("Appearance" is cut off).
- **Fix:** merge into 5 sections:
  - **You:** profile plus theme.
  - **Courses:** picker, add by code, Moodle, ResoBin.
  - **Notifications:** alerts, digest, personal email, calendar link.
  - **Interests**.
  - **Account:** export, sign out, delete.

**C3 · P3 · Wrong panel copy**
- "Appearance: You can also switch from the sidebar." Phones have no sidebar, only the header icon, so say "from the sun/moon button at the top".
- The My courses copy mentions ResoBin slots; simplify it to "Your timetable is built from these."

**C4 · P3 · My courses order**
- **Problem:** in Settings, "Import from ResoBin" (which needs a laptop extension) comes above the picker.
- **Fix:** put the picker first, as setup now does, with ResoBin and Moodle in a collapsed "On a laptop?" block.

## D. Home

**D1 · P2 · Saved and All next to search look like filters for the current tab**
- **Where:** `FeedView.tsx:81-104`.
- **Fix:** move Saved and All to the end of the tabs row, separated by a divider, or into a single "⋯ More" menu. Keep search on its own.

**D2 · P3 · Section notes read like developer notes**
- **Where:** `FeedView.tsx:10-18`, for example "pinned until you tick Done or the date passes. Soonest first."

**D3 · P3 · The "Done" button is the loudest thing on every card**
- **Where:** `ItemCard.tsx`.
- **Fix:** make it a small ghost "✓ Done" next to Save. Keep the bright treatment only for items due in under 48 hours.

**D4 · P3 · A holiday shows as a day of struck-out classes**
- **Where:** `src/app/page.tsx:22-58`.
- **Fix:** if every row of the chosen day is cancelled by a `*` (all courses) update, show "No classes today — Institute holiday" (use the notice's subject) instead of five struck rows.

**D5 · P3 · Wide screens leave a big empty right side**
- **Problem:** at 1280 px and above, the content sits left with about 30% blank on the right.

## E. Timetable

**E1 · P2 · The "Cancel" button on every class is risky and unclear**
- **Where:** `TimetableView.tsx:166`.
- **Problem:** a student reads "Cancel" as cancelling the class, and it's one accidental tap away.
- **Fix:** move it into a per-class "⋯" menu labelled "Mark as cancelled (only for me)", with Undo.

**E2 · P3 · Phone header is cramped**
- **Where:** `src/app/schedule/page.tsx:278-290`.
- **Problem:** "This week · updates itself from notices" wraps, and Add slot / Export stack beside the title.
- **Fix:** put the eyebrow on its own line and the two buttons as icons in one row, or move them into a "⋯" menu.

**E3 · P3 · "Add slot" asks for slot codes**
- **Where:** `CoursesEditor.tsx:127`, placeholder "2A 2B 2C".
- **Problem:** first-years don't know slot codes.
- **Fix:** let them pick day and time, and keep the slot codes as an "advanced" field.

**E4 · P3 · Weekends**
- **Problem:** the day strip is Mon–Fri only. Saturday extra classes or labs added through notices or "Add slot" are invisible.
- **Fix:** show Sat/Sun chips only when that day has something.

## F. Library

**F1 · P2 · An empty tab for most students**
- **Problem:** Library only fills with Moodle connected, which needs a laptop extension. Phone-only students get a permanently empty tab in the bottom bar.
- **Fix:** if no `moodle_connections` row exists, hide Library from the phone bottom bar, or show an empty state that explains what they'd get plus "Connect from a laptop: Settings → Courses".

**F2 · P3 · Sync interval mismatch**
- **Problem:** "updated every 30 min" (`library/page.tsx:28`, `admin/page.tsx:67`) is wrong; the Moodle sync runs every 15 min (pg_cron `moodle-sync`). Fix the copy.
